# Handover document — Brew & Bean Clinic System

## 1. What you are receiving
A full MERN application (API + React UI), automated tests, Docker image, CI/CD pipeline and Render configuration. Start with `README.md`, then `docs/ARCHITECTURE.md`.

## 2. Accounts and secrets you must own
| Item | Where it lives | Action |
|---|---|---|
| MongoDB Atlas cluster | Atlas | Create your own; put the URI in Render `MONGO_URI` |
| `JWT_SECRET`, `JWT_REFRESH_SECRET` | Render env vars | Generated by Render; rotate yearly (everyone must log in again) |
| `RENDER_DEPLOY_HOOK_URL`, `APP_URL` | GitHub Actions secrets | Add after creating the Render service |
| First admin account | Database | Create it, then change the password; delete the demo users |

Never commit `.env`. `.gitignore` already excludes it.

## 3. Daily operations
* **Deploy:** merge/push to `main`; CI runs lint → tests → Docker → Render deploy hook.
* **Health:** `GET /api/health`. Render uses it as the health check.
* **Logs:** Render dashboard → Logs (HTTP access logs + errors).
* **Backups:** Atlas free tier has no automatic backups. Schedule `mongodump` (or upgrade the cluster) — patient data is irreplaceable.
* **Who did what:** Admin → *Audit log* page, or `GET /api/audit-logs`.

## 4. Common maintenance tasks
| Task | How |
|---|---|
| Add a doctor with a login | Doctors page → *New doctor*; then Users page → *New account* (role Doctor, pick the profile) |
| Link a login to an existing patient | Users page → role Patient → pick the patient record |
| Disable someone who left | Users page → *Disable* (their tokens stop working immediately) |
| Change a doctor's hours | `PATCH /api/doctors/:id` with `workingDays`, `workingHours`, `slotMinutes` |
| Change token lifetime / upload limit | Env vars `ACCESS_TOKEN_EXPIRES_IN`, `MAX_UPLOAD_MB` |
| Add a new audited model | `schema.plugin(auditPlugin, { entity: 'Name' })` and add the name to `validators/report.js` |

## 5. Known limitations (be honest with the client)
1. **Prescription images are on local disk.** On Render free tier they disappear on redeploy. Fix: replace `middleware/upload.js` + `getPrescription` with an S3/Cloudinary storage engine (the rest of the code only uses `filename`). Until then use a paid Render disk.
2. Free Render instances sleep → first request after idle takes ~30-50 s.
3. Audit entries don't contain old/new values (privacy choice). Add a snapshot field if regulators require it.
4. Refresh tokens live in `localStorage`; consider httpOnly cookies + CSRF protection for higher security.
5. No e-mail/SMS reminders, password reset or two-factor login yet.
6. No daylight-saving handling (fixed UTC offset).
7. Single active session per user.
8. The `seed` script deletes all data — development only.

## 6. Suggested next steps
Cloud file storage · password reset by e-mail · appointment reminders · 2FA for doctors/admins · scheduled backups · structured logging (pino) and error tracking (Sentry).

## 7. Troubleshooting
| Symptom | Likely cause |
|---|---|
| Server exits "Missing required environment variables" | Set `JWT_SECRET`, `JWT_REFRESH_SECRET`, `MONGO_URI` |
| `401 Token expired` loops | Clock wrong on the server/client, or refresh token was already used (log in again) |
| Calendar shows no free slots | Doctor not selected, doctor has no working day that week, or `CLINIC_TZ_OFFSET_MINUTES` wrong |
| Upload returns 415 | File is not a real JPEG/PNG/WebP |
| `409 This time slot is already booked` | Overlap with another visit of the same doctor |
| CORS error in browser | Add the site URL to `CORS_ORIGIN` |
| Tests hang on first run | They are downloading the in-memory MongoDB; or set `MONGO_URI_TEST` |
